docker compose up --build
Ця команда збере образи заново, налаштує внутрішню мережу, підключить постійний том (Persistent Volume) для MySQL та запустить додаток.
Запуск у фоновому режимі (Detached Mode)
Якщо ви хочете звільнити термінал для подальшої роботи, запустіть контейнери у фоновому режимі за допомогою прапорця -d:

Bash
docker compose up -d
Звичайний запуск (без перезбірки шарів)
Якщо конфігурація не змінювалася, достатньо виконати:

Bash
docker compose up
🛑 2. Зупинка проєкту
Залежно від того, як ви запускали контейнери, є два способи їх зупинки.

Спосіб A: Термінал заблоковано (контейнери запущені в прямому режимі)
Якщо ви бачите логи контейнерів у поточному вікні термінала, просто натисніть комбінацію клавіш:

Ctrl + C

Docker Compose надішле сигнал SIGTERM процесам всередині контейнерів і безпечно їх зупинить протягом кількох секунд.

Спосіб B: Контейнери запущені у фоновому режимі (-d)
Якщо контейнери працюють у фоні, виконайте команду в тій самій папці проєкта:

Bash
docker compose stop
Ця команда зупиняє контейнери, але зберігає їх стан, мережі та внутрішні ідентифікатори.

🧹 Повне видалення контейнерів та мереж
Щоб не просто зупинити контейнери, а й повністю видалити їх разом із тимчасовими мережами проєкту, скористайтеся командою down:

Bash
docker compose down
⚠️ Зверніть увагу: Команда docker compose down видаляє контейнери та мережі, але НЕ видаляє ваші Todos (дані з MySQL), оскільки база підключена до Persistent Volume (db_data), який залишається недоторканим у системі.

🔍 3. Перевірка статусу та діагностика (Troubleshooting)
Перевірка статусу контейнерів та Healthcheck
Щоб дізнатися, чи пройшла MySQL перевірку на працездатність (healthcheck) і чи працює додаток, виконайте:

Bash
docker compose ps
Ви побачите таблицю зі статусами (Up (healthy), Exit 0 тощо) та прокинутими портами.

Перегляд логів у реальному часі
Якщо ви запустили проєкт у фоновому режимі (-d) і хочете подивитися, що відбувається всередині Django або MySQL, скористайтеся командою відстежування логів:

Bash
docker compose logs -f
Щоб вийти з режиму перегляду логів, натисніть Ctrl + C (це не зупинить самі контейнери).

Перевірка стану Persistent Volume
Для перевірки наявності постійного сховища, де зберігаються Todos, можна виконати команду:

Bash
docker volume ls
Ви повинні побачити у списку том із назвою <ім'я_папки>_db_data.

🧹 4. Повне очищення (Reset інфраструктури)
Якщо вам потрібно повністю видалити інфраструктуру разом із даними бази даних (наприклад, для повного перезапуску міграцій «з нуля»), виконайте команду down із прапорцем -v (volumes):

Bash
docker compose down -v
🚨 Попередження: Ця команда безповоротно видалить Persistent Volume db_data та всі ваші збережені завдання (Todos). Наступний запуск docker compose up --build створить абсолютно порожню базу даних та запустить міграції заново.
